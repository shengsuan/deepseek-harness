# Agent Note: ShengSuanYun router adapter over the Anthropic Messages wire format

Status: implemented

English | [中文](2026-08-19-shengsuanyun-anthropic-router-adapter.zh.md)

## Problem

[Provider-routed LLM adapters](../architecture/2026-07-14-provider-routed-llm-adapters.md) made provider a registration key independent of model, so a router that fronts many backing models needs only one adapter, not one per backing model. ShengSuanYun (胜算云) is such a router: it exposes DeepSeek, Qwen, GLM, Kimi, GPT, and Claude models behind one endpoint that speaks the Anthropic Messages wire format, plus a separate proprietary model-listing endpoint. Every existing adapter is a genuine twin — `dsh-llm-deepseek` hand-rolls fetch and SSE parsing, `dsh-llm-pi-ai` delegates to a provider-abstraction library — but neither exercises a third-party *client SDK* driving the harness's own translation layer, and no existing adapter's catalog has to reconcile per-backing-model reasoning axes that disagree within one provider.

`@anthropic-ai/sdk` was already a repo dependency (used by `dsh-subagent-claude-code`) but had no direct Messages-API consumer, so the adapter is also the first place harness code translates `RawMessageStreamEvent` into `StreamChunk`.

## Decision

`dsh-llm-shengsuanyun` registers the single provider route `shengsuanyun` and constructs an `@anthropic-ai/sdk` client per operation with `baseURL` set to the configured endpoint (no `/v1` suffix — the SDK itself appends the literal `/v1/messages` path). `apiKey` is the resolved credential; the SDK's default `x-api-key` request header satisfies ShengSuanYun's documented `X-Api-Key` (HTTP header names are case-insensitive). A model string reaches the router unvalidated against the catalog — catalog membership is advisory only, matching every other adapter's convention — so a new backing model behind the router reaches this adapter without a code change.

The model catalog is a separate raw `fetch` against `modelsURL`, filtered to entries whose `support_apis` includes `/v1/messages`, cost-mapped by dividing `pricing.{prompt,completion,cache}` by the wire's 10,000 scaling factor, and TTL-cached (5 minutes, single-flight, stale-serve on a failed refetch when a prior cache exists). Each model's reasoning control is looked up by longest-prefix match on its id against a fixed table mirroring ShengSuanYun's own documented per-model axes (`deepseek/deepseek-v4`, `deepseek/deepseek-v3`, `openai/gpt-5.`, `ali/qwen3`, `bigmodel/glm-4.7`, `bigmodel/glm-5`, `moonshot/kimi`, `openai/o`, `anthropic/claude`). A model whose entry declares an `effort` axis exposes those exact named levels under `reasoning.efforts`, dispatching to Anthropic's `output_config: {effort}` field; a model with only `toggle`/`budget_tokens` axes instead exposes a synthetic `off`/`on` pair dispatching to `thinking: {type: 'disabled'|'enabled'|'adaptive'}` (`budget_tokens` clamped below the request's `max_tokens` when the table declares a minimum). A model absent from the table declares no reasoning control; selecting an id a model's axis does not declare fails `UNSUPPORTED_REASONING_EFFORT` before network I/O, mirroring `dsh-llm-pi-ai`'s `resolveReasoningLevel()`.

Assistant-turn serialization replays the exact native Anthropic content blocks captured in this adapter's own prior `finish.replayState` when available, preserving `thinking` signatures and tool-use ids/inputs across turns. A turn without a stored `replayState` — produced by a different adapter, or history predating this feature — projects lossily instead: `text`/`tool-call` blocks convert directly, and `reasoning` blocks are dropped, because a fabricated `thinking` signature fails Anthropic's server-side validation. `tool-result` messages become standalone user-role `tool_result` blocks, one per message, matching the harness's one-result-per-message vocabulary. Only text content is accepted inbound (`UNSUPPORTED_CONTENT` for any image block before network I/O), since the catalog declares `inputModalities: ['text']` only.

Streaming translation follows the same `content_block_start`/`_delta`/`_stop`, `message_delta`, `message_stop` event sequence as the Anthropic SDK's own documented protocol; a stream that exhausts before `message_stop` throws `STREAM_CLOSED`, and a `stop`-kind finish with zero emitted content blocks maps to `EMPTY_RESPONSE_CODE` (both conventions already established by `dsh-llm-deepseek`). Server-tool and other block types this adapter never requests reserve their index and emit no deltas or `block-end` — a documented Known Limitation rather than a translation gap, since the adapter's own request never opens one. Response usage (`input_tokens`/`output_tokens`/`cache_read_input_tokens`/`cache_creation_input_tokens`) is already disjoint on the wire, unlike DeepSeek's folded `prompt_tokens`, so no subtraction is needed.

Errors classify by `instanceof` against the SDK's typed error hierarchy rather than text matching — `AuthenticationError`/`PermissionDeniedError` → `AUTH`, `RateLimitError` → `RATE_LIMIT` with `providerRetryAfterMs` parsed from the `retry-after` header, `BadRequestError` → `CONTEXT_WINDOW_EXCEEDED`/`QUOTA`/`INVALID_REQUEST` via the shared detail classifiers, `InternalServerError` → `SERVER`, `APIConnectionTimeoutError` → `TIMEOUT`, `APIConnectionError` → `TRANSPORT`, `APIUserAbortError` → `ABORTED`, any other `APIError` → `HTTP_<status>`, each carrying `requestId` from the provider's request-id header when present.

Dynamic configuration (`ctx.settings`, `ctx.credentials`) and the registration-captured retry policy follow `dsh-llm-deepseek`'s established thunk pattern exactly: connection facts resolve once per operation, an in-flight stream keeps the facts it started with, and a settings snapshot the resolver rejects contributes neither its endpoint nor its key.

## Alternatives considered

- **A raw `fetch` + hand-rolled SSE parser**, matching `dsh-llm-deepseek`'s own internals. Rejected: the SDK is already a repo dependency, the spec explicitly asks to use it when available, and doing so exercises the SDK-consumer pattern the twin-adapter design deliberately left uncovered.
- **One adapter per backing model family** (a DeepSeek-shaped adapter, a Claude-shaped adapter, etc.), mirroring the granularity of the native provider adapters. Rejected: ShengSuanYun's own transport is uniform Anthropic Messages regardless of backing model, so per-family adapters would duplicate the identical translation layer for no capability gain, and would defeat the router's own value of adding backing models without a code change.
- **Route-level (not model-level) reasoning defaults**, matching the original `dsh-llm-pi-ai` shape. Rejected for the same reason [the per-model reasoning declarations Agent Note](2026-08-08-pi-ai-per-model-reasoning-declarations.md) rejected it upstream: ShengSuanYun's own backing models disagree about which reasoning axes they accept, so a single route-level knob cannot be set without breaking part of the route.

## Consequences

- The harness gains a router-style provider whose backing-model set can grow without a Cordis plugin change, verified against the same `StreamChunk` vocabulary every other adapter proves out.
- The Models page's model-fetch action interrogates the `llm-shengsuanyun` namespace through `ctx.llm.registerModelDiscovery`, answered from the same TTL-cached catalog as `listModels()` — no second listing fetch, and the probe's `baseURL` is ignored because the listing endpoint is the plugin's own `modelsURL`, not the Messages `baseURL`.
- `@anthropic-ai/sdk` now has an in-repo Messages-API consumer beyond `dsh-subagent-claude-code`, so an SDK upgrade that changes `OutputConfig`, error class shapes, or stream event types is caught by this package's typecheck and tests too, not only the subagent backend's.
- The prefix-table reasoning lookup is a maintained artifact, not derived from the catalog response: a ShengSuanYun-side change to a backing model's reasoning axes requires a matching table edit in this package, silently falling back to "no reasoning control" until corrected.
- `tool_choice` is not mapped (shared gap with `dsh-llm-deepseek` and `dsh-llm-pi-ai`); the model-listing `fetch` does not go through `@cordisjs/plugin-http`, so it has no shared proxy/interception configuration until a second adapter wants one.

## Testing

Unit coverage exercises the reasoning-lookup table, cost scaling, `support_apis` filtering, TTL/stale-cache behavior, event-stream-to-`StreamChunk` translation including replay-state round-trips and the refusal/empty-response/stream-closed edge cases, and SDK error-class-to-`LlmError` code mapping. A real-composition Loader test covers settings/credential hot-reload, retry-policy re-registration, and restart persistence. A keyless snapshot fixture exercises the adapter through an assembled example, and a `SHENGSUANYUN_API_KEY`-gated e2e test hits the real endpoint.
